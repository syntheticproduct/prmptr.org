# Part 1 — Recovery strategy

**Rebuild difficulty:** EASY
(Everything needed to build and run is committed and pushed. Verified 2026-08-23: working

## What this is
Tauri (Rust + Next.js + Milkdown) desktop app for prompt engineering — a markdown editor
plus a browser over local Claude Code / Claude Desktop session data. It owns no database:
it reads and writes files that already exist on the machine. A small static landing page
(`landing/`) ships separately to Cloudflare Workers as the worker `prmptr-org`.

## Rebuild from scratch
1. `gh repo clone syntheticproduct/prmptr.org && cd prmptr.org`
2. Node: `.nvmrc` pins 24.15.0 and CI installs from it. `.npmrc` sets `engine-strict=true`,
   but `package.json` only declares `engines.node >= 22.0.0` — so npm refuses Node 20 and
   older, and lets Node 22/23 through even though nothing is tested on them. Use 24.15.0.
   Rust 1.95.0 installs itself from `rust-toolchain.toml` via rustup.
3. `sudo apt install libwebkit2gtk-4.1-dev libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev pkgconf`
4. Windows cross-build from WSL: `sudo apt install mingw-w64 nsis`. No `rustup target add`
   needed — `rust-toolchain.toml` already declares `targets = ["x86_64-pc-windows-gnu"]`.
5. `npm ci` — `package-lock.json` and `src-tauri/Cargo.lock` are both committed.
6. Credentials, only if publishing: `gh auth login` (clone/push; **releases build in GitHub
   Actions on a `v*.*.*` tag using the automatic `GITHUB_TOKEN`, so no local token is
   involved**), `npx wrangler login` (landing page). Optional `cp .env.example .env.local`
   holds two commented `NEXT_PUBLIC_*` dev conveniences, no secrets.
7. Verify: `npm run check && npm run test:unit && npm run test:rust`, then `npm run tauri dev`.
   CI is stricter than `npm run check` — it also runs `cargo fmt --check` and
   `cargo clippy --all-targets -- -D warnings`, on both ubuntu and windows runners.
   Windows artifact: `npm run tauri build -- --target x86_64-pc-windows-gnu --bundles nsis`.

## Gotchas
- `.gitignore` lists `CLAUDE.md`, `AGENTS.md` and `.claude/`, but the two md files are
  force-tracked and current. A *new* file matching those patterns is silently skipped by
  `git add` — use `git add -f`.
- `CLAUDE.md` still instructs agents to copy Tauri PNG icons into fresh worktrees before
  building, claiming they are gitignored. **That is stale and self-propagating** — `CLAUDE.md`
  loads into every session in this repo, so each agent re-learns the wrong thing. Verified
  2026-08-23: `.gitignore` re-includes `!src-tauri/icons/**/*.png` and all 33 PNGs plus
  `icon.icns` / `icon.ico` are tracked. Skip that step; fix the instruction when convenient.
- `.claude/worktrees/` is **26 GB** — almost entirely four copies of `node_modules` and
  `src-tauri/target`. It holds no unique commits (see above). Never back it up; never delete
  the worktrees either, they are intentional parallel workspaces.
- No code signing: `release.yml` has the signing env vars commented out, so Windows builds
  are unsigned and SmartScreen warns "Unknown publisher". Nothing to recover.
- `npm run test:e2e` needs `npx playwright install chromium` — six of the seven scripts in
  `tests/e2e/` launch chromium directly.
- `test-editor.mjs` at the repo root is gitignored playwright scratch, not part of the suite.
- The Rust side honours `PRMPTR_COWORK_PATH` and `PRMPTR_COWORK_LOCALSTORAGE_PATH`; set them
  to point the app at a restored session tree in a non-default location.

## Tactical — copy before the wipe

| what | source path (on C:) | size | destination | already covered? |
|---|---|---|---|---|
| App UI prefs — pinned library order, folder-pane root + width, last tab/view/frontmatter mode (LevelDB, live state) | `C:\Users\camil\AppData\Local\org.prmptr.app\EBWebView\Default\Local Storage` | 9,254 B (9 KB, 6 files) | `D:\_backup\projects\prmptr.org\localstorage` | **No.** The manifest's `windows` tree covers `C:\Users\camil\.claude`, `.config`, `projects` and loose home files — it never sweeps `AppData\Local`, and `claude-management-backup` only covers Claude's own AppData trees |

That is the entire list. One row, 9 KB.

**Quiesce first** — this is a live LevelDB the app writes to; a copy taken mid-write can be
unreadable. There is no dump utility, so the equivalent is to stop the writer. Close the
prmptr.org window, then confirm nothing holds it:

```
powershell.exe -NoProfile -Command "Get-Process prmptr -ErrorAction SilentlyContinue | Select-Object Id,ProcessName"
```

Empty output = safe to copy. If it prints a PID, close the app (or
`Stop-Process -Name prmptr`) and re-run.

**Copy now:**

```
robocopy "C:\Users\camil\AppData\Local\org.prmptr.app\EBWebView\Default\Local Storage" "D:\_backup\projects\prmptr.org\localstorage" /E /R:1 /W:1 /NP /LOG+:D:\_backup\logs\prmptr-org.log
```

**Optional, and worth the 3 seconds** — the roadmap design handoff. It *is* covered, inside
the 122.3 GB WSL image, so it does not earn a table row. But it is the one artifact this
project cannot regenerate, and pulling 50 KB out means it survives without restoring a
whole disk image. Run from WSL (the source is a Linux path):

```
mkdir -p "/mnt/d/_backup/projects/prmptr.org/roadmap" && cp -a /home/camille/.claude/projects/-home-camille/memory/refs/prmptr-roadmap/. "/mnt/d/_backup/projects/prmptr.org/roadmap/"
```

No `/MIR`, no `/PURGE`, no `rsync --delete` anywhere above — `D:\_backup` is a shared
destination and a mirroring sync scoped to this tree would delete other jobs' only copies.

TOTAL: 59 KB (9 KB required + 50 KB optional), under 1 minute.
